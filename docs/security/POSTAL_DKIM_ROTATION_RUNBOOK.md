# Postal DKIM rotation and MoneyBee email activation gate

## Security decision

All existing Postal DKIM signing keys for the configured domains are designated **compromised and mandatory for rotation**. Do not copy, paste, print, archive, or reuse any previously exposed private key.

MoneyBee registration, verification, password recovery, invitation, and welcome email must remain disabled for public use until the canonical `moneybeeloan.com` sender has completed the rotation and acceptance checks in this runbook.

This document is an operator plan only. It does not authorize an unreviewed change to Postal, DNS, Keycloak, Codestra middleware, Odoo, or the MoneyBee server.

## Canonical MoneyBee email identity

Use:

```text
Sender domain: moneybeeloan.com
From: MoneyBee Accounts <accounts@moneybeeloan.com>
Reply-To: MoneyBee Support <support@moneybeeloan.com>
```

`moneybee.loan` is not the canonical authentication sender unless a later reviewed change explicitly selects it.

Use the verified Postal SMTP host and port from the live runtime inventory. Do not assume that `smtp.moneybeeloan.com`, an internal Postal container address, or port `2525` is reachable from Keycloak until the network path, TLS mode, firewall, and credentials have been verified.

## Per-domain rotation procedure

Perform this process in a controlled maintenance window for every configured domain.

1. Record the domain, old selector name, current DNS TTL, operator, change ID, and rollback owner. Never record the private key.
2. Reduce the old DKIM TXT record TTL in advance where operationally possible.
3. Generate a new DKIM key and a new selector inside the approved Postal administrative path.
4. Publish the new selector TXT record exactly as generated by Postal.
5. Verify the new TXT record from more than one public resolver.
6. Confirm Postal recognizes the new DKIM record.
7. Switch Postal signing to the new selector.
8. Send a controlled test message to an external mailbox and inspect the raw headers.
9. Require `dkim=pass`, `spf=pass`, and the expected DMARC alignment. Confirm the return-path belongs to the intended Postal domain.
10. Remove the old selector TXT record as soon as the new selector is proven. Keeping the old public key published leaves the exposed private key usable for forgery.
11. Delete or disable the old signing key in Postal.
12. Search approved secret stores, host files, shell history, diagnostics, tickets, transcripts, CI artifacts, backups, and operator workstations for unauthorized copies. Do not put discovered key material into GitHub comments or evidence files.
13. Repeat the test after the old selector has been removed.
14. Save only non-secret evidence: domain, new selector name, DNS response hash, Postal check result, message ID, header-result summary, timestamps, and operator approval.

## MoneyBee-specific acceptance checks

Before Keycloak may send email through `moneybeeloan.com`, require:

```text
MONEYBEE_POSTAL_DKIM_ROTATED=PASS
MONEYBEE_POSTAL_OLD_SELECTOR_REMOVED=PASS
MONEYBEE_POSTAL_SPF=PASS
MONEYBEE_POSTAL_DKIM=PASS
MONEYBEE_POSTAL_DMARC_ALIGNMENT=PASS
MONEYBEE_POSTAL_MX=PASS
MONEYBEE_POSTAL_RETURN_PATH=PASS
MONEYBEE_POSTAL_TLS=PASS
MONEYBEE_POSTAL_BOUNCE_HANDLING=PASS
MONEYBEE_POSTAL_SUPPRESSION_HANDLING=PASS
KEYCLOAK_SMTP_TEST=PASS
KEYCLOAK_VERIFY_EMAIL_TEST=PASS
KEYCLOAK_PASSWORD_RESET_TEST=PASS
KEYCLOAK_EXPIRED_LINK_TEST=PASS
KEYCLOAK_WRONG_RECIPIENT_TEST=PASS
```

Then test the durable welcome-email path separately:

```text
ACCOUNT_REGISTERED_OUTBOX=PASS
CODESTRA_INBOX=PASS
KLYROW_WELCOME_EMAIL_SANDBOX=PASS
ODOO_CONTACT_PROJECTION_SANDBOX=PASS
SIGNED_CODESTRA_RECEIPT=PASS
DUPLICATE_DELIVERY=PASS
REPLAY_REJECTION=PASS
DEAD_LETTER_AND_REQUEUE=PASS
```

## Fail-closed activation policy

Until all acceptance evidence is reviewed:

```dotenv
MIDDLEWARE_PROVIDER=disabled
ENABLE_EXTERNAL_DELIVERY=false
ODOO_WRITE=false
N8N_DELIVERY_ENABLED=false
```

Keycloak SMTP credentials must remain in Keycloak or an approved secret manager. They must never be committed to Git, embedded in frontend builds, stored in MoneyBee PostgreSQL, written to outbox payloads, or included in Docker image metadata.

## Evidence record

Create one non-secret record per domain:

```text
CHANGE_ID=
DOMAIN=
OLD_SELECTOR_REMOVED=YES|NO
NEW_SELECTOR=
DNS_TTL=
DNS_CHECKED_AT=
POSTAL_CHECK=PASS|FAIL
SPF=PASS|FAIL
DKIM=PASS|FAIL
DMARC_ALIGNMENT=PASS|FAIL
MX=PASS|FAIL
RETURN_PATH=PASS|FAIL
TLS=PASS|FAIL
TEST_MESSAGE_ID=
HEADER_EVIDENCE_SHA256=
OPERATOR=
REVIEWER=
ROLLBACK_TEST=PASS|FAIL
```

Never include a private key, SMTP password, Postal API credential, access token, or full sensitive message body in this record.
